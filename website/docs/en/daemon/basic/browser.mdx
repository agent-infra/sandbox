# Browser API

aiod attaches to an existing Chromium; it does not launch the browser. Two environment variables decide where it attaches:

| Variable | Default | Meaning |
| --- | --- | --- |
| `BROWSER_REMOTE_DEBUGGING_HOST` | `127.0.0.1` | Host carrying Chromium's debugging port |
| `BROWSER_REMOTE_DEBUGGING_PORT` | `9222` | Chromium's debugging port |

Use a CDP client such as Playwright or Puppeteer, or call the REST API directly. `/v1/browser/*` and `/v2/browser/*` use the same request bodies. The exception is desktop input: v1 uses `POST /v1/browser/actions`, while v2 uses `/v2/computer`. See [**Computer Use**](/daemon/basic/display).

## CDP

### Get the CDP URL

aiod asks the Chromium at `BROWSER_REMOTE_DEBUGGING_HOST:PORT` for `/json/version`, takes its `webSocketDebuggerUrl`, and rewrites it from the request headers:

| Part | Taken from |
| --- | --- |
| Host | `X-Forwarded-Host`, or `Host` when absent |
| Scheme | `wss` when `X-Forwarded-Proto` is `https`, otherwise `ws` |
| Path prefix | `X-Forwarded-Prefix`, empty when absent |

<ApiV2>

```bash
# BASE_URL=https://sandbox.example.com
curl "$BASE_URL/v2/browser/info"
```

</ApiV2>

<ApiV1>

```bash
# BASE_URL=https://sandbox.example.com
curl "$BASE_URL/v1/browser/info"
```

</ApiV1>

```json
{
  "data": {
    "cdp_url": "wss://sandbox.example.com/cdp/devtools/browser/46164812-5f92-4ec5-891a-8c138aeb93a4",
    "cdp_ui_url": null
  }
}
```

When Chromium does not answer, `cdp_url` still comes back in the same shape as a placeholder; call again once it recovers.

Playwright and Puppeteer connect to `cdp_url` directly; see [Browser (CDP)](/daemon/examples/browser-cdp). Reverse proxies, path prefixes, and key parameters are covered on [CDP Access](/daemon/basic/cdp).

### Send a raw CDP command

| Route | Purpose | Notes |
| --- | --- | --- |
| `POST /cdp` | Send one raw CDP command | The result lands in `data` |

Use it for what REST does not cover. For a sequence of commands, connect over `cdp_url` instead.

For actions that don't need a full CDP client, aiod serves a small REST set. Every route returns the standard `{success, message, data}` envelope; full schemas are in the [API Reference](/daemon/api).

`navigate`, `evaluate`, `snapshot`, `click`, `fill`, `upload`, and `cdp` accept `tab_id` and use the first tab without it. `screenshot` does not accept `tab_id` and always captures the first tab.

### Navigate and evaluate

| Route | Purpose | Notes |
| --- | --- | --- |
| `POST /navigate` | Load a URL, or move through history | Takes `url` or `history`; `url` wins if both arrive |
| `POST /evaluate` | Run JavaScript in the page's main world | Returns the value; `await_promise` waits for a Promise |

```json
{
  "url": "https://example.com",
  "wait_until": "load"
}
```

- `wait_until` is `load`, `domcontentloaded`, `networkidle`, or `commit`; the default is `load`.
- `timeout` defaults to 30 seconds; a timeout answers `503`, and the tab remains usable.
- `history` accepts `back`, `forward`, or `reload`.
- `evaluate` puts the result in `data.value` and JavaScript exceptions in `data.exception`; the HTTP status stays `200`.

### Take a screenshot

| Route | Purpose | Notes |
| --- | --- | --- |
| `GET /screenshot` | Capture the current page | The response body is the image |

`format` is `png` (default), `jpeg`, or `jpg`; `quality` is 0–100 for jpeg and defaults to 85. `full_page=true` captures the whole scrollable page. PNG responses carry `x-image-width` and `x-image-height`.

### Page snapshots

| Route | Purpose | Notes |
| --- | --- | --- |
| `POST /snapshot` | Return the page structure | `interactive_only` keeps actionable elements |
| `POST /click` | Click an element | By `ref` or CSS `selector` |
| `POST /fill` | Fill an input | By `ref` or CSS `selector` |
| `POST /upload` | Upload a file | By `ref` or CSS `selector` |

A `ref` comes from `snapshot`. Take a new snapshot after each navigation; refs from the old document are no longer valid.

### Tabs

| Route | Purpose | Notes |
| --- | --- | --- |
| `GET /tabs` | List tabs | Each entry has `id`, `title`, `url`, `type` |
| `POST /tabs` | Open a tab | `url` is optional and defaults to `about:blank` |
| `POST /tabs/{tab_id}/activate` | Bring a tab to the front | Moves it to the head of the list; an unknown id is a `404` |
| `DELETE /tabs/{tab_id}` | Close a tab | An unknown id is a `404` |

A new tab goes to the head of the list and becomes the default target.

### Cookies

| Route | Purpose | Notes |
| --- | --- | --- |
| `POST /cookies` | Set cookies | Body is `cookies`, a list; the reply counts them |
| `GET /cookies` | Read them back | Narrows by `url` or `domain` |
| `DELETE /cookies` | Delete one, or all of them | `name` plus `url` or `domain`, or `all=true` |

The shape is CDP's own. A cookie needs a `name` and either a `url` or a `domain` with a `path`; the other fields are optional.

### The request log

| Route | Purpose | Notes |
| --- | --- | --- |
| `GET /network/requests` | Read-only log of page requests | `limit` caps the result, `clear=true` empties the buffer after reading |

Collection starts on the first call and keeps the latest 300 requests. Interception and header rewriting are not supported.

### Window size

| Route | Purpose | Notes |
| --- | --- | --- |
| `POST /config` | Resize the browser window over CDP | `resolution` must be a supported size; other values answer `422` |

Omitting `resolution` leaves the window unchanged.

### Error semantics

| Status | Meaning |
| --- | --- |
| `400` | A required parameter is missing or the body is not JSON |
| `404` | An element or tab does not exist |
| `422` | A parameter value is unsupported |
| `503` | CDP is unreachable, navigation timed out, or CDP execution failed |

JavaScript exceptions are not HTTP errors: `evaluate` answers `200` with `data.exception`.

## MCP tools

An MCP-capable agent calls browser tools through `/mcp`. The daemon itself carries `browser_get_info`, plus `browser_gui_screenshot` and `browser_gui_execute_action` when computer-use is available.

The AIO image runs [`@agent-infra/mcp-server-browser`](https://github.com/bytedance/UI-TARS-desktop/tree/main/packages/agent-infra/mcp-servers/browser) on loopback and registers it as an upstream of `/mcp`, which is where the image's page-level `browser_*` navigation tools come from. See [MCP](/daemon/examples/mcp) for how registration works.

## CDP, REST tools, or MCP

All three operate on the same Chromium:

| Way in | Gives | Costs |
| --- | --- | --- |
| CDP client | Full page automation | A CDP client and WebSocket |
| REST API | Common browser operations | One operation per request |
| MCP | Browser operations as tools | An MCP client |

Use CDP for full page automation, REST for common operations, and MCP when the agent already speaks MCP.

## Human in the loop

A person can watch or take over the Chromium the agent is driving. Both viewers attach to the same browser environment:

| Viewer | Path | Shows |
| --- | --- | --- |
| noVNC | `/vnc/index.html?autoconnect=true` | The whole desktop: Chromium, dialogs, other windows |
| DevTools | `/browser-ui`, `/cdp/devtools/*` | The current Chromium page |

noVNC attaches to the desktop, not to one browser window, so the file dialog, the address bar and other application windows are all reachable, and the desktop survives a Chromium restart. The noVNC page embeds in an iframe.

Person and agent share one browser state: after a login completed in noVNC, the agent's next `snapshot` reads the logged-in page.

The daemon serves the API only; the image's gateway serves the noVNC and DevTools pages. Deployment and access are described on [**Computer Use**](/daemon/basic/display#human-in-the-loop).
