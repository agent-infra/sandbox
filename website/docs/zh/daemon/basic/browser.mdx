# 浏览器 API

aiod 连接已经启动的 Chromium，不负责启动浏览器。连接地址由两个环境变量决定：

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `BROWSER_REMOTE_DEBUGGING_HOST` | `127.0.0.1` | Chromium 调试端口所在主机 |
| `BROWSER_REMOTE_DEBUGGING_PORT` | `9222` | Chromium 调试端口 |

可以使用 Playwright、Puppeteer 等 CDP 客户端，也可以直接调用 REST API。`/v1/browser/*` 和 `/v2/browser/*` 的请求体相同；桌面操作除外：v1 使用 `POST /v1/browser/actions`，v2 使用 `/v2/computer`。详见 [**Computer Use**](/zh/daemon/basic/display)。

## CDP

### 获取 CDP URL

aiod 向 `BROWSER_REMOTE_DEBUGGING_HOST:PORT` 上的 Chromium 请求 `/json/version`，取其中的 `webSocketDebuggerUrl`，再按请求头改写成对外地址：

| 组成 | 取值 |
| --- | --- |
| 主机 | `X-Forwarded-Host`，没有则取 `Host` |
| 协议 | `X-Forwarded-Proto` 为 `https` 时用 `wss`，否则用 `ws` |
| 路径前缀 | `X-Forwarded-Prefix`，没有则为空 |

<ApiV2>

```bash
# BASE_URL=https://sandbox.example.com
curl "$BASE_URL/v2/browser/info"
```

</ApiV2>

<ApiV1>

```bash
# BASE_URL=https://sandbox.example.com
curl "$BASE_URL/v1/browser/info"
```

</ApiV1>

```json
{
  "data": {
    "cdp_url": "wss://sandbox.example.com/cdp/devtools/browser/46164812-5f92-4ec5-891a-8c138aeb93a4",
    "cdp_ui_url": null
  }
}
```

Chromium 没有应答时，`cdp_url` 仍按同样格式返回一个占位地址，恢复后重新调用即可。

Playwright 和 Puppeteer 直接连接 `cdp_url`，示例见 [浏览器（CDP）](/zh/daemon/examples/browser-cdp)。反向代理、路径前缀和鉴权参数的处理见 [CDP 接入](/zh/daemon/basic/cdp)。

### 发送原始 CDP 命令

| 路由 | 作用 | 说明 |
| --- | --- | --- |
| `POST /cdp` | 发送一条原始 CDP 命令 | 结果放在 `data` 里 |

REST 没有覆盖的能力走这个入口。需要连续发多条命令时，直接用 `cdp_url` 建立 CDP 连接。

`navigate`、`evaluate`、`snapshot`、`click`、`fill`、`upload` 和 `cdp` 可以用 `tab_id` 指定标签页，不传时作用于列表中的第一个标签页。`screenshot` 不支持 `tab_id`，始终截取第一个标签页。

### 导航与脚本执行

| 路由 | 作用 | 说明 |
| --- | --- | --- |
| `POST /navigate` | 加载 URL，或在历史记录里移动 | 传 `url` 或 `history`，两者都传时以 `url` 为准 |
| `POST /evaluate` | 在页面主世界里执行 JavaScript | 按值返回结果，`await_promise` 会等待 Promise |

```json
{
  "url": "https://example.com",
  "wait_until": "load"
}
```

- `wait_until` 可选 `load`、`domcontentloaded`、`networkidle`、`commit`，默认 `load`。
- `timeout` 默认 30 秒，超时返回 `503`，标签页仍可继续使用。
- `history` 可取 `back`、`forward`、`reload`。
- `evaluate` 的结果在 `data.value`，JavaScript 异常在 `data.exception`，HTTP 状态仍是 `200`。

### 截图

| 路由 | 作用 | 说明 |
| --- | --- | --- |
| `GET /screenshot` | 截取当前页面 | 响应体就是图片 |

`format` 可选 `png`（默认）、`jpeg`、`jpg`；`quality` 取 0–100，只对 jpeg 生效，默认 85。`full_page=true` 截取整个可滚动页面。PNG 响应带 `x-image-width` 和 `x-image-height`。

### 页面快照

| 路由 | 作用 | 说明 |
| --- | --- | --- |
| `POST /snapshot` | 返回页面结构 | `interactive_only` 只保留可操作元素 |
| `POST /click` | 点击元素 | 用 `ref` 或 CSS `selector` |
| `POST /fill` | 填写输入框 | 用 `ref` 或 CSS `selector` |
| `POST /upload` | 上传文件 | 用 `ref` 或 CSS `selector` |

`ref` 来自 `snapshot`。每次导航后都要重新取快照，旧的 `ref` 不再有效。

### 标签页

| 路由 | 作用 | 说明 |
| --- | --- | --- |
| `GET /tabs` | 列出标签页 | 每项包含 `id`、`title`、`url`、`type` |
| `POST /tabs` | 打开标签页 | `url` 可选，默认 `about:blank` |
| `POST /tabs/{tab_id}/activate` | 把标签页切到最前 | 它会移到列表最前面，未知 id 返回 `404` |
| `DELETE /tabs/{tab_id}` | 关闭标签页 | 未知 id 返回 `404` |

新打开的标签页排在列表最前面，并成为默认目标。

### Cookie

| 路由 | 作用 | 说明 |
| --- | --- | --- |
| `POST /cookies` | 设置 cookie | body 里的 `cookies` 是一个列表，响应返回条数 |
| `GET /cookies` | 读取 cookie | 可按 `url` 或 `domain` 收窄 |
| `DELETE /cookies` | 删除一条或全部 | `name` 配合 `url` 或 `domain`，或者 `all=true` |

结构沿用 CDP 的定义。设置时必须提供 `name`，以及 `url` 或 `domain` 和 `path`，其他字段可选。

### 请求日志

| 路由 | 作用 | 说明 |
| --- | --- | --- |
| `GET /network/requests` | 页面请求的只读日志 | `limit` 限制条数，`clear=true` 读取后清空 |

从第一次调用后开始收集，最多保留最近 300 条。不支持请求拦截和请求头改写。

### 窗口大小

| 路由 | 作用 | 说明 |
| --- | --- | --- |
| `POST /config` | 通过 CDP 调整窗口大小 | `resolution` 必须是支持的尺寸，其他组合返回 `422` |

不传 `resolution` 时不修改窗口。

### 错误处理

| 状态码 | 说明 |
| --- | --- |
| `400` | 参数缺失或请求体不是 JSON |
| `404` | 元素或标签页不存在 |
| `422` | 参数值不受支持 |
| `503` | CDP 不可达、导航超时或 CDP 执行失败 |

JavaScript 异常不算 HTTP 错误：`evaluate` 仍返回 `200`，异常放在 `data.exception` 里。

## MCP 工具

支持 MCP 的 agent 通过 `/mcp` 调用浏览器工具。daemon 自带 `browser_get_info`，以及 computer-use 可用时的 `browser_gui_screenshot` 和 `browser_gui_execute_action`。

AIO 镜像在 loopback 上运行 [`@agent-infra/mcp-server-browser`](https://github.com/bytedance/UI-TARS-desktop/tree/main/packages/agent-infra/mcp-servers/browser)，并把它注册成 `/mcp` 的上游，镜像里页面级的 `browser_*` 导航工具由此而来。注册方式见 [MCP](/zh/daemon/examples/mcp)。

## 选择调用方式

三种入口操作的是同一个 Chromium：

| 入口 | 提供 | 代价 |
| --- | --- | --- |
| CDP 客户端 | 完整的页面自动化能力 | 需要 CDP 客户端和 WebSocket |
| REST API | 常用浏览器操作 | 一次请求执行一个操作 |
| MCP | 以工具形式调用浏览器 | 需要 MCP 客户端 |

需要完整的页面自动化时使用 CDP；只做常用操作时直接调用 REST API；已经接入 MCP 的 agent 可以使用 MCP。

## Human in the loop

人可以直接查看或接管 agent 正在操作的 Chromium。两种查看方式连接的是同一个浏览器环境：

| 查看方式 | 地址 | 可以看到 |
| --- | --- | --- |
| noVNC | `/vnc/index.html?autoconnect=true` | 整个桌面，包括 Chromium、对话框和其他窗口 |
| DevTools | `/browser-ui`、`/cdp/devtools/*` | 当前 Chromium 页面 |

noVNC 连接的是整个桌面，而不是单独的浏览器窗口。因此可以操作文件选择框、地址栏和其他应用窗口。即使 Chromium 重启，桌面仍会保留。noVNC 页面也可以嵌入 iframe。

人和 agent 共享同一个浏览器状态。例如，在 noVNC 中完成登录后，agent 下一次调用 `snapshot` 就能看到登录后的页面。

daemon 只提供 API；noVNC 和 DevTools 页面由镜像网关提供。部署和访问方式见 [**Computer Use**](/zh/daemon/basic/display#human-in-the-loop)。
